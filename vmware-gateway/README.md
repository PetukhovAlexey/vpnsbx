# vmgw — роутер для виртуальных машин VMware с выходом в интернет по профилям AmneziaWG

Комплект разворачивает в VMware Workstation (Windows) такую схему:

```
                Windows (этот компьютер)
                   │ VMnet1 host-only (или VMnet8), напр. 192.168.9.0/24
                   │ панель http://192.168.9.10:8088, SSH
          ┌────────┴─────────┐
          │  vmgw-router     │ mgmt0  .10
          │  Ubuntu Server   │ wan0   bridged → физическая сеть → интернет
          │                  │          (опционально через корпоративный OpenVPN)
          │                  │ lan0   .1  ── LAN segment (внутренний коммутатор)
          └──────────────────┘                    │
                    ┌──────────────┬──────────────┼──────────── …
                  ws1 (.10)      ws2 (.11)      ws3 (.12)     Ubuntu Desktop,
                  профиль A      профиль B      без профиля   одна сетевая карта
```

## Модель доступа

* **Внутри всё открыто.** ВМ сегмента общаются друг с другом напрямую (L2, роутер не участвует)
  и с компьютером Windows в обе стороны (через роутер, без ограничений по портам).
* **Интернет — только по профилю.** Каждой ВМ на роутере назначается свой профиль AmneziaWG.
  Трафик ВМ в глобальную сеть уходит только в её туннель. Если туннель не поднят, сервер недоступен
  или профиль не назначен, интернета у ВМ нет (fail-closed, без «утечки» напрямую).
* **ВМ без профиля** (новая, ещё не зарегистрированная) получает адрес из DHCP-пула .200–.250,
  видит соседей и Windows, но в интернет не выходит. В панели она видна в разделе
  «ВМ без профиля» — её можно сразу добавить кнопкой «Добавить как хост».
* Обход через NAT-шлюз VMware (.2 сети управления) и через DNS компьютера Windows закрыт.
  DNS ВМ получают по DHCP (1.1.1.1, 9.9.9.9) — запросы идут через туннель ВМ.
* «Домашняя сеть» (флажок у хоста, `vmgw host local`): разрешить ВМ доступ к локальной сети
  за WAN (например, к принтеру или NAS). По умолчанию выключено.
* Режим `direct` (без VPN, напрямую через WAN) есть, но включается только явно, для отдельной ВМ.
* **Корпоративный OpenVPN** (необязательно) — общий транспорт: при включении все туннели
  AmneziaWG строятся через него, при выключении — напрямую. Переключается разом для всех.
  Если корпоративный VPN включён, но не поднялся, туннели не уходят «в обход» — интернета нет.
  Сервер корпоративного VPN должен выпускать трафик в интернет (до серверов AmneziaWG).
* Проброс портов: внешний порт роутера → порт ВМ, доступ со стороны Windows (`mgmt`) или из
  домашней сети за WAN (`local`). Так, например, доступен SSH на ВМ без выставления их наружу.

## Что нужно

* Windows 10/11, VMware Workstation 17 или новее (Pro, бесплатная для личного использования).
* В Virtual Network Editor у VMnet1 (по умолчанию) включён «Connect a host virtual adapter».
* Образы Ubuntu **только с официального сайта** (комплект их не содержит и не скачивает):
  * роутер — **Ubuntu Server** LTS: <https://ubuntu.com/download/server>;
    при установке можно выбрать вариант «Ubuntu Server (minimized)»;
  * ведомые ВМ — **Ubuntu Desktop** LTS: <https://ubuntu.com/download/desktop>
    или **Windows 10/11**: <https://www.microsoft.com/software-download/windows11>
    (см. «Ведомая ВМ с Windows»).
  * Все выпуски и контрольные суммы: <https://releases.ubuntu.com/>. Установщик сам сверяет
    SHA256 образа с `SHA256SUMS` на releases.ubuntu.com (отключить: `-SkipIsoCheck`).
* Профили AmneziaWG (файлы `.conf`/`.vpn`) — свои для каждой ВМ или общие.

## Установка

### 1. Создать ВМ (Windows)

Запустите `Setup.cmd` (или `windows\New-VmGwLab.ps1` в PowerShell). Без параметров он спросит
оба ISO в окне выбора файла и создаст роутер и одну ВМ `ws1`. Примеры:

```bat
Setup.cmd -Clients ws1,ws2,ws3
Setup.cmd -ServerIso D:\iso\ubuntu-24.04.3-live-server-amd64.iso -DesktopIso D:\iso\ubuntu-24.04.3-desktop-amd64.iso
Setup.cmd -AddClient ws4                  :: ещё одна ВМ в существующую лабораторию
```

Основные параметры:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `-LabDir` | `Документы\Virtual Machines\VmGw` | папка лаборатории |
| `-Clients` | `ws1` | имена ведомых ВМ (латиница, цифры, дефис) |
| `-AddClient ИМЯ` | | добавить ВМ в готовую лабораторию (`lab.json`) |
| `-ClientOs`, `-WindowsIso` | `ubuntu` | с `-AddClient`: `windows` — ВМ под Windows 10/11 и её ISO |
| `-MgmtVnet` | `VMnet1` | сеть управления: `VMnet1` (host-only) или `VMnet8` (NAT) |
| `-LanNet` | `192.168.150.0/24` | адреса LAN-сегмента (/16 … /24) |
| `-SshPort`, `-PanelPort` | `22`, `8088` | порты роутера в сети управления |
| `-AdminNets` | | доп. сети, откуда пускать в панель/SSH через WAN, напр. `192.168.31.0/24` |
| `-LocalNets` | `auto` | «домашняя сеть» за WAN: `auto` (сеть WAN), `none` или список |
| `-RouterMemoryMB/-RouterCpus/-RouterDiskGB` | 1024 / 1 / 16 | |
| `-ClientMemoryMB/-ClientCpus/-ClientDiskGB` | 4096 / 2 / 40 | |
| `-SshPublicKey ФАЙЛ`, `-NoSshKey` | `~\.ssh\id_ed25519.pub` и т.п. | публичный ключ для входа на роутер (только .pub) |
| `-HwVersion` | по версии Workstation | `virtualHW.version` |
| `-NoRoute`, `-NoOpen`, `-SkipIsoCheck` | | не добавлять маршрут / не открывать VMware / не сверять SHA256 |

Что делает скрипт:

* создаёт роутер (3 сетевые карты: управление, LAN segment, bridged WAN) и ВМ (одна карта в LAN segment),
  статические MAC-адреса, общую папку `vmgw` (только чтение) с комплектом `kit\`;
* пишет `kit\lab.conf` (MAC-адреса, сети, порты, список ВМ) и `lab.json`;
* предлагает добавить в Windows постоянный маршрут к LAN-сегменту через роутер
  (нужны права администратора; иначе выполните выведенную команду `route -p add …` сами);
* открывает ВМ в VMware.

Если в Windows уже есть адрес из `-LanNet` или он пересекается с VMnet — скрипт остановится
и попросит другую сеть. Если у bridged-сети несколько физических адаптеров, выберите нужный
в Virtual Network Editor (VMnet0 → Bridged to).

### 2. Установить роутер

1. Включите `vmgw-router`, установите Ubuntu Server. Настройки сети в установщике не меняйте
   (DHCP на всех картах), отметьте «Install OpenSSH server».
2. После установки войдите в консоль ВМ и выполните:
   ```bash
   sudo mkdir -p /mnt/hgfs
   sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
   sudo bash /mnt/hgfs/vmgw/router-install.sh
   ```
   Если `vmhgfs-fuse` не найден (minimized): `sudo apt install open-vm-tools`.
   Вместо общей папки можно скопировать `kit` по SSH: `scp -r kit пользователь@адрес:` и
   запустить `sudo bash kit/router-install.sh`.
3. Скрипт:
   * ставит пакеты (nftables, dnsmasq, openvpn, python3);
   * собирает amneziawg-go и amneziawg-tools из исходников (Go — официальный, с go.dev,
     с проверкой sha256);
   * переименовывает карты в `mgmt0/lan0/wan0` по MAC, настраивает netplan, DHCP-сервер,
     межсетевой экран, службы и SSH (ключ из `lab.conf`);
   * регистрирует ВМ из `lab.conf`;
   * спрашивает пароль панели и предлагает перезагрузиться.
   Старые настройки сети сохраняются в `/root/vmgw-backup-*`.
   Повторный запуск безопасен; `sudo REBUILD=1 bash router-install.sh` пересоберёт AmneziaWG.
4. После перезагрузки роутер доступен с Windows: `http://192.168.9.10:8088` (адрес — тот, что вывел
   установщик) и `ssh -p 22 пользователь@192.168.9.10`.

### 3. Профили

В панели → «Профили» загрузите файлы AmneziaWG, затем в «Хосты» назначьте каждой ВМ профиль.
То же из консоли:

```bash
sudo vmgw profile import ~/riga.conf riga.vpn
sudo vmgw host set ws1 tunnel riga.vpn
sudo vmgw status
```

### 4. Установить ведомые ВМ

Включите ВМ и установите Ubuntu Desktop. Интернет в ВМ появится, только когда ей назначен профиль
и туннель работает, поэтому установку можно делать без обновлений. По желанию, после установки:

```bash
sudo mkdir -p /mnt/hgfs && sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
sudo bash /mnt/hgfs/vmgw/client-setup.sh          # проверка сети и внешнего IP
sudo bash /mnt/hgfs/vmgw/client-setup.sh --ssh    # + OpenSSH-сервер и ваш ключ
```

`client-setup.sh` покажет внешний адрес: он должен совпадать с сервером профиля этой ВМ.

### Добавить ВМ позже

```bat
Setup.cmd -AddClient ws4
```

Затем на роутере — в панели «ВМ без профиля» → «Добавить как хост» (ВМ появится там, как только
получит адрес по DHCP) или `sudo vmgw host add ws4 MAC` (MAC выводит скрипт), и назначьте профиль.
После регистрации ВМ получает постоянный адрес .10–.199 при следующем продлении DHCP
(быстрее — переподключить сеть в ВМ или перезагрузить её).

Лаборатория не в папке по умолчанию (`Документы\Virtual Machines\VmGw`) — добавьте `-LabDir ПАПКА`.
Контур, собранный без `Setup.cmd`, тоже можно описать файлом `lab.json` в этой папке: поля `Router`
(`MgmtMac`, `LanMac`, `WanMac`, `Vmx`), `Clients` (`Name`, `Mac`, `Vmx`), `PvnId` (как `ethernetN.pvnID`
LAN-карты роутера в его .vmx), `MgmtAddr`, `SshPort`, `PanelPort` и др. — как в файле, который создаёт
`Setup.cmd`. Пути `Vmx` могут указывать в любые папки; новые ВМ создаются в папке лаборатории.

### Ведомая ВМ с Windows

```bat
Setup.cmd -AddClient win1 -ClientOs windows -WindowsIso D:\iso\Win11_24H2_Russian_x64.iso
```

Windows-ВМ получает адрес, DNS и выход через туннель от роутера так же, как Ubuntu: внутри ничего
от vmgw ставить не нужно, общей папки с комплектом у неё нет, а обновлялка её пропускает.
Скрипт создаёт ВМ под установщик Windows: диск NVMe (не меньше 64 ГБ), сетевая карта e1000e
(драйвер есть в самой Windows), EFI с Secure Boot, не меньше 4 ГБ памяти и 2 ядер.
Если в имени ISO есть `Win10`, ВМ настраивается под Windows 10, иначе под Windows 11.

1. Зарегистрируйте ВМ на роутере и назначьте ей профиль **до установки**: установщику Windows 11
   нужен интернет, и он будет только через туннель.
2. Windows 11 требует TPM 2.0, а VMware добавляет виртуальный TPM только зашифрованной ВМ. Поэтому
   для Windows 11 скрипт подключает вторым CD маленький образ `win11-setup.iso` с `autounattend.xml`:
   установщик сам находит его и отключает проверки TPM, Secure Boot и памяти (ключи
   `HKLM\SYSTEM\Setup\LabConfig`). Остальные вопросы установщик задаёт как обычно. Настоящий vTPM
   по желанию: VM Settings → Options → Access Control → Encrypt, затем Hardware → Add → Trusted
   Platform Module. Если образ создать не удалось (или ВМ создана старой версией скрипта) и
   установщик пишет «Компьютер должен поддерживать доверенный платформенный модуль 2.0», нажмите
   там Shift+F10 и выполните:
   ```bat
   reg add HKLM\SYSTEM\Setup\LabConfig /v BypassTPMCheck /t REG_DWORD /d 1 /f
   reg add HKLM\SYSTEM\Setup\LabConfig /v BypassSecureBootCheck /t REG_DWORD /d 1 /f
   ```
   затем закройте консоль, вернитесь на шаг назад и снова нажмите «Далее». Для Windows 10 TPM не нужен.
3. Установите Windows, затем VM → Install VMware Tools (драйвер экрана, буфер обмена).

## Обновление

```bat
Update.cmd               :: обновить все запущенные ВМ лабораторий до версии комплекта
Update.cmd -CheckOnly    :: только показать версии
Update.cmd -RebuildAwg   :: заодно пересобрать AmneziaWG на роутере (туннели переподнимутся)
Update.cmd -Force        :: переустановить, даже если версия совпадает
```

Обновляются только запущенные ВМ: сначала роутер, затем ведомые (по SSH с ключом; ведомым нужен
`client-setup.sh --ssh`). Ведомые ВМ с Windows пропускаются — им софт vmgw не нужен. Пароль sudo вводится в окне Update.cmd. Хосты, профили, пробросы и пароль
панели не меняются; копия заменённых файлов — в `/var/lib/vmgw/update-backup`, при ошибке откат
выполняется сам. Вручную, без Windows: `sudo bash /mnt/hgfs/vmgw/update.sh router` (или `client`).

Поддерживаются Ubuntu 18.04 и новее (Python 3.6+, OpenVPN 2.4+: параметры OpenVPN 2.5+ из профиля
корпоративного VPN переводятся в старый синтаксис).

## Окно VPN-песочницы

VPN-песочница (vpnsbx) ставит этот комплект в `Program Files\VPN-песочница\vmgw`, а в её окне есть
вкладка «VMware-контур»: лаборатории из `Документы\Virtual Machines\VmGw` и подключённых папок,
их ВМ (запущена ли, версия софта), кнопки «Панель роутера», «SSH», «Проверить версии»,
«Обновить…», «+ ВМ…» (Ubuntu или Windows), «Новая лаборатория…». Окно запускает те же
`New-VmGwLab.ps1` и `Update-VmGwLab.ps1`; там, где нужен пароль sudo или ответы, открывается
отдельное окно консоли.

Под списком лабораторий — сама панель роутера, по вкладке на каждую лабораторию. Окно ходит в API
панели напрямую (тот же пароль; «запомнить» хранит его зашифрованным DPAPI для текущего
пользователя Windows) и показывает всё, что умеет роутер: хосты и их профили, ВМ без профиля,
туннели, корпоративный VPN, профили, проброс портов, «Применить конфигурацию». Набор разделов
берётся из ответа роутера как есть: у роутера старой версии будут только его функции, а данные,
которых окно не знает, видны в «Прочие данные роутера». «В браузере» открывает обычную панель.

## Панель

`http://<адрес роутера>:8088`, вход по паролю (сменить: `sudo vmgw panel-password`).
Разделы: хосты (профиль, режим, «Домашняя сеть»), ВМ без профиля, туннели (состояние, перезапуск),
корпоративный VPN, профили, проброс портов, журнал. Панель доступна только из сети управления и
`ADMIN_NETS`; работает от отдельного пользователя `vmgw-web` и вызывает `vmgw` через sudo
с ограниченным набором действий.

## Консоль

```
vmgw status                          состояние туннелей, хостов, пробросов
vmgw apply                           применить сохранённую конфигурацию
vmgw restart [ПРОФИЛЬ]               перезапустить туннели (все или один)
vmgw stop                            остановить все туннели (хосты остаются без выхода)
vmgw profile list|import ФАЙЛ [ИМЯ.vpn]|delete ИМЯ
vmgw host list|add ИМЯ MAC [IP]|del ИМЯ
vmgw host set ИМЯ tunnel ПРОФИЛЬ | direct | blocked
vmgw host local ИМЯ on|off           доступ к домашней сети за WAN
vmgw fwd list|add tcp|udp ВНЕШНИЙ_ПОРТ ХОСТ ПОРТ [mgmt|local]|del tcp|udp ВНЕШНИЙ_ПОРТ
vmgw leases                          DHCP-аренды (в т.ч. ВМ без профиля)
vmgw corp import ФАЙЛ.ovpn | credentials | on | off
vmgw panel-password
```

Все команды — через `sudo`.

### Проброс портов

```bash
sudo vmgw fwd add tcp 2201 ws1 22          # с Windows: ssh -p 2201 user@192.168.9.10
sudo vmgw fwd add tcp 8443 ws2 443 local   # из домашней сети за WAN: https://<WAN роутера>:8443
```

Раз есть маршрут Windows → LAN, с Windows можно ходить и прямо на адрес ВМ (`ssh user@192.168.150.10`);
пробросы нужны для доступа из домашней сети или если маршрут не добавлен.

### Корпоративный OpenVPN

```bash
sudo vmgw corp import client.ovpn
sudo vmgw corp credentials      # если профиль требует логин/пароль
sudo vmgw corp on               # все туннели — через корпоративный VPN
sudo vmgw corp off              # напрямую
```

Из `.ovpn` убираются скрипты, маршруты и DNS-настройки сервера: корпоративный VPN используется
только как путь до серверов AmneziaWG, весь остальной трафик роутера и ВМ через него не идёт.

## Безопасность

* Комплект не содержит профилей, ключей, паролей и адресов серверов — всё загружается на месте.
  Профили и учётные данные хранятся на роутере в `/etc/vmgw` (доступ только root и группе панели).
* В `lab.conf` попадает только **публичный** ключ SSH.
* Общая папка `vmgw` подключена только на чтение; после установки её можно отключить
  в настройках ВМ (Options → Shared Folders).
* IPv6 в сегменте отключён (иначе он мог бы стать путём в обход туннелей).
* Панель: пароль (PBKDF2), cookie HttpOnly/SameSite, ограничение попыток входа, проверка
  Origin/Host, CSP. Работает по HTTP — не открывайте её в недоверенные сети.

## Диагностика

```bash
sudo vmgw status                      # туннели, рукопожатия, хосты
sudo vmgw leases                      # кто получил адрес по DHCP
sudo nft list ruleset | less          # правила
ip rule; ip route show table 51801    # маршрутизация (таблица туннеля 1)
journalctl -b -u vmgw -u 'vmgw-awg@*' -u vmgw-web -u 'openvpn-client@vmgw-corp'
sudo awg show
```

* ВМ не получает адрес — проверьте, что её карта в том же LAN segment, что и `lan0` роутера
  (ВМ → Settings → Network Adapter → LAN segment), и что `dnsmasq` запущен.
* Нет интернета у ВМ с профилем — `vmgw status`: нет рукопожатия → сервер недоступен с WAN
  (или через корпоративный VPN); при `corp on` проверьте `systemctl status openvpn-client@vmgw-corp`.
* Windows не видит ВМ — `route print 192.168.150.*`; маршрут должен вести на адрес роутера
  в сети управления.
* Если на Windows работает другой VPN с «полным туннелем», он может перехватывать bridged-трафик:
  проверка внешнего адреса в ВМ покажет адрес того VPN. Временно выключите его.

```
Setup.cmd                 запуск установщика
windows/New-VmGwLab.ps1   создание ВМ в VMware Workstation
guest/router-install.sh   установка роутера (Ubuntu Server)
guest/client-setup.sh     проверка/донастройка ведомой ВМ
guest/vmgw/vmgw.py        контроллер: туннели, маршруты, nftables, DHCP
guest/vmgw/vmgw-web.py    веб-панель
guest/vmgw/systemd/       юниты systemd и хук networkd-dispatcher
```
